Week 2: Internet Architecture (TCP/IP, DNS, HTTP/HTTPS, Web Applications) 1. Relevance Assessment & The Missing Links . Standard internet governance courses focus heavily on Western network topologies. In East Africa, data transport frequently crosses international boundaries through subsea fiber -optic cables and terrestrial gateways managed by various tier-1 internet service providers (ISPs) like MTN, Airtel, and Roke Telecom. When a Ugandan user accesses a local web application, their data packets may route through servers in Europe or South Africa before returning. This reality creates a complex compliance challenge for data residency and privacy. If a lawyer doesn't understand the stateless nature of HTTP or how the Domain Name System (DNS) can be spoofed, they won't be able to effectively litigate cross-border data protection violations or unauthorized wiretapping claims. 2. Weekly Actionable Learning Outcomes & Topics . Actionable Learning Outcomes: * Trace the physical and logical path of a data packet to identify when it enters or exits Ugandan regulatory jurisdiction. * Deconstruct the DNS resolution process to detect and litigate digital identity theft and domain hijacking. Topics Covered: The Network Stack: The 5-layer Internet Protocol Stack (Application, Transport, Network, Link, Physical) vs. the 7-layer OSI Model. TCP/IP Suite: Packet encapsulation, IP addressing, routing principles, and the difference between reliable transport (TCP) and connectionless transport (UDP). The Domain Name System (DNS): Distributed hierarchical databases, name-to-IP resolution, and DNS caching records. HTTP/HTTPS & Web Applications: Request/Response models, the stateless nature of web protocols, cookies, session state preservation, and TLS/SSL encryption integration. 3. Vital Reading Resources . The "Foundation-to-Tune" Comparative Analysis The Global/Engineering Foundation: Internet architecture relies on dynamic packet routing across international borders using the TCP/IP stack, treating every router hop purely as an infrastructure optimization choice. The Ugandan Practice Tune: Section 19 of the Data Protection and Privacy Act, strictly prohibits the transfer of a Ugandan citizen's personal data outside the country unless the destination country has adequate protection laws. By understanding packet routing and application proxy behaviour , a Ugandan lawyer can look at an application's server logs to prove that a clients sensitive data was routed through a non-compliant foreign proxy server, demonstrating a statutory breach even if the application's user interface appears local. 5. Weekly LDC-Style Practice Task The Jurisdictional Data Map & Opinion: A mobile health application registered in Kampala collects maternal health data from users in Western Uganda. The application uses a local cloud proxy service, but the backend database is physically hosted in a data center in Ohio, USA. Reviewing an engineer's network topology diagram, draft a formal Legal Advisory Opinion for the Personal Data Protection Office (PDPO). Trace the path of a user's HTTPS request from a smartphone in Mbarara, through the DNS resolution phase, the ISP gateway network hop, and finally to the US database server. Identify exactly which network layers and physical hops trigger Section 19 compliance duties under the Data Protection and Privacy Act , and state whether the current network setup is lawful without explicit data subject consent.
