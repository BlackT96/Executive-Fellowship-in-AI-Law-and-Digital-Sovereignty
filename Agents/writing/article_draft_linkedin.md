When a server crashes, Ugandan law asks one question: "Did the computer fail?"

The real question should be: "Which layer of the computer failed?"

Here is the problem.

Uganda's Computer Misuse Act and Sale of Goods Act treat "the computer" as a single thing. But every technologist knows a computer is a stack of distinct layers:

1. Hardware (chips, RAM, storage)
2. Operating System (kernel, drivers, process scheduler)
3. Application Software
4. Network

Each layer has a different manufacturer, a different vendor, and a different legal relationship with the end user.

A chip overheats — that is a hardware defect. A kernel panic follows — that is a symptom, not a separate cause. An OS misconfiguration allows privilege escalation — that is a software or system integrator issue, not a hardware problem.

Current Ugandan law cannot cleanly separate these. The result? Litigants waste years joining multiple defendants because the statute does not tell them which layer to sue at.

Other jurisdictions are moving past this. The EU's proposed AI Liability Directive distinguishes between hardware, software, and AI-system defects. The UK's Product Security and Telecommunications Infrastructure Act 2022 imposes different duties on manufacturers, software vendors, and network providers.

Uganda's tech regulations need a layer-aware framework. Until they get one, every system failure case is a guessing game dressed up as litigation.
