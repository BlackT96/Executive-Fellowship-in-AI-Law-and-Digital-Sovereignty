Week 3: Databases (SQL, NoSQL, Data Warehouses) 1. Relevance Assessment &amp; The Missing Links Many standard legal definitions of a "record" assume structured, unalterable paper documents or rigid data tables. However, modern Ugandan enterprise architectures-especially in high-velocity fintech, mobile money, and micro-lending systems-frequently use NoSQL data structures and centralized data lakes to process unstructured consumer data. In a commercial dispute before the Commercial Division of the High Court of Uganda, proving that a digital financial transaction took place requires verifying database log integrity. If an attorney cannot differentiate between an ACID-compliant relational database and a BASE-compliant distributed NoSQL database, they will fail to properly authenticate or challenge digital evidence under the statutory frameworks that govern electronic transactions. 2. Weekly Actionable Learning Outcomes &amp; Topics Actionable Learning Outcomes: * Evaluate the transactional consistency of a database system to determine if data deletion or modification complied with statutory data retention laws. * Assess the architectural integrity of serverless data warehouses to compile legally admissible system audit trails. Topics Covered: SQL (Relational Databases): Tables, schemas, primary/foreign keys, structured querying, vertical scaling, and ACID properties (Atomicity, Consistency, Isolation, Durability). NoSQL (Non-Relational Databases): Document stores, key-value pairs, graph databases, horizontal scaling, and the BASE property model (Basically Available, Soft state, Eventual consistency). Data Warehousing &amp; Serverless Analytics: Centralized data storage architectures, ETL (Extract, Transform, Load) pipelines, and big data analysis systems (e.g., Google BigQuery ). 3.
