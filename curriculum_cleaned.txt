EXECUTIVE FELLOWSHIP CURRICULUM: AI LAW &amp; DIGITAL SOVEREIGNTY MODULE 1: Digital Technology Fundamentals Objective: To enable the learner to communicate effectively with engineers, software developers, cybersecurity professionals, regulators, and policymakers, translating technical computational realities into robust legal strategies within the Ugandan and regional legal landscape. Week 1: Computer Systems (Hardware, Software, OS, Networks) 1. Relevance Assessment &amp; The Missing Links Western technology textbooks assume a highly structured corporate ecosystem where hardware procurement and software deployment follow predictable, standardized lifecycles. In Ugandan practice, tech litigators frequently encounter hybrid or grey-market hardware setups, open-source operating systems deployed without corporate support, and erratic local network infrastructures. A Ugandan attorney must understand abstraction layers to effectively cross-examine technical experts or draft product liability pleadings under local commercial laws. You cannot establish whether a system crash or security breach resulted from a manufacturing hardware defect, an operating system misconfiguration, or an unauthorized software patch unless you can legally isolate these technical layers. 2. Weekly Actionable Learning Outcomes &amp; Topics Actionable Learning Outcomes: Isolate the exact layer of a computational failure to determine proper defendants in a technology product liability suit. Deconstruct operating system resource management to identify whether a data breach was caused by internal user privilege escalation or external network intrusion. Topics to be Covered: Introduction to Computer Systems: Abstraction levels from digital logic (gates, transistors) to high-level programming languages. Hardware vs. Software: Processor architectures (x86 vs. ARM), memory hierarchy (RAM, cache, storage), and firmware boundaries. Operating Systems (OS) as Resource Containers: Kernels, processes, threads, memory allocation, and user privilege management. Networks: Local Area Networks (LAN) vs. Wide Area Networks (WAN); the concept of the network edge (hosts, clients) versus the network core (routers, switches). 3. Week 2: Internet Architecture (TCP/IP, DNS, HTTP/HTTPS, Web Applications) 1. Relevance Assessment &amp; The Missing Links . Standard internet governance courses focus heavily on Western network topologies. In East Africa, data transport frequently crosses international boundaries through subsea fiber -optic cables and terrestrial gateways managed by various tier-1 internet service providers (ISPs) like MTN, Airtel, and Roke Telecom. When a Ugandan user accesses a local web application, their data packets may route through servers in Europe or South Africa before returning. This reality creates a complex compliance challenge for data residency and privacy. If a lawyer doesn't understand the stateless nature of HTTP or how the Domain Name System (DNS) can be spoofed, they won't be able to effectively litigate cross-border data protection violations or unauthorized wiretapping claims. 2. The Domain Name System (DNS): Distributed hierarchical databases, name-to-IP resolution, and DNS caching records. HTTP/HTTPS &amp; Web Applications: Request/Response models, the stateless nature of web protocols, cookies, session state preservation, and TLS/SSL encryption integration. 3. Week 3: Databases (SQL, NoSQL, Data Warehouses) 1. Relevance Assessment &amp; The Missing Links Many standard legal definitions of a "record" assume structured, unalterable paper documents or rigid data tables. However, modern Ugandan enterprise architectures—especially in high-velocity fintech, mobile money, and micro-lending systems—frequently use NoSQL data structures and centralized data lakes to process unstructured consumer data. In a commercial dispute before the Commercial Division of the High Court of Uganda, proving that a digital financial transaction took place requires verifying database log integrity. If an attorney cannot differentiate between an ACID-compliant relational database and a BASE-compliant distributed NoSQL database, they will fail to properly authenticate or challenge digital evidence under the statutory frameworks that govern electronic transactions. 2. Weekly Actionable Learning Outcomes &amp; Topics Actionable Learning Outcomes: * Evaluate the transactional consistency of a database system to determine if data deletion or modification complied with statutory data retention laws. * Assess the architectural integrity of serverless data warehouses to compile legally admissible system audit trails. Topics Covered: SQL (Relational Databases): Tables, schemas, primary/foreign keys, structured querying, vertical scaling, and ACID properties (Atomicity, Consistency, Isolation, Durability). NoSQL (Non-Relational Databases): Document stores, key-value pairs, graph databases, horizontal scaling, and the BASE property model (Basically Available, Soft state, Eventual consistency). Data Warehousing &amp; Serverless Analytics: Centralized data storage architectures, ETL (Extract, Transform, Load) pipelines, and big data analysis systems (e.g., Google BigQuery ). 3.
